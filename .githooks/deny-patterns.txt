# Deny patterns for the public repo. One extended-regex per line, POSIX ERE (grep -E).
#
# GENERIC PATTERNS ONLY. This file is public. An exact private literal written here is
# published by the very commit that adds it — escaping a dot conceals nothing. Exact
# literals belong in the private supplement (CASA_DENY_SUPPLEMENT), never here. That
# applies to path patterns too: a private artefact's filename describes the shape of the
# private tree, so the artefact names live in the supplement as well.
#
# This file is excluded from the generic CONTENT sweep by path, since it necessarily
# contains the patterns it defines. It is NOT excluded from secret scanning, its grammar
# is tested, and the private supplement's exact literals ARE swept against it.
#
# [allow-content] entries are stripped from the text before the GENERIC rules run, so the
# project's own public strings do not trip a generic rule. They are NOT stripped before
# the private supplement's rules run — an allow entry must never be able to blind an
# exact-literal rule. Allow entries name ONE value: a rule broad enough to whole-match an arbitrary
# canary is refused, since it would exempt unrelated findings.

# Value-shaped, not identifier-shaped, and `$` excluded so that indirection through a
# config lookup or a variable is not a hit. Casa's own source legitimately contains every
# one of these identifiers; what must never appear is an assigned LITERAL.
#   `_webhook_secret="$(bashio::config 'webhook_secret')"`  -> fine, contains $
#   `webhook_secret="9f3c...."`                             -> hit
