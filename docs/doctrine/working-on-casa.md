# Working on Casa

> Code is the source of truth. This file is a map; when it and the code disagree, the code wins.

## Scope

How to change this repository without breaking it, and how to establish that a claim about it
is true. It is aimed at an agent doing the work. It does not cover how an agent should behave
at runtime; that is `doctrine/operating-casa.md`.

## Mental model

Most of what goes wrong here is not a bad edit. It is a **confident statement about behaviour
that nobody verified** — a check assumed to be universal, a symbol assumed to be gone, a
guarantee assumed to be wider than it is. Every document in this corpus that had to be
corrected was corrected for that reason, not for a typo.

So the discipline is about evidence, and it is specific.

## Verification discipline

**Read whole files, not grep slices.** A slice tells you a line matched. It does not tell you
what the surrounding function does with it, and reasoning from the slice is how a true fact
becomes a false claim.

**Never conclude something is gone from an anchored search.** An anchored pattern for a
method cannot match a function nested inside another function. This exact mistake put "this
was removed" into a document and a commit message about a function that was live and
load-bearing. Search unanchored across the whole tree, then read what you find.

**Follow the call chain before saying what the system does.** A loader that returns early does
not tell you the system boots — something further up may refuse. A claim about startup needs
the startup path, not the first function on it.

**Count the callers before assuming a helper is universal.** A validator that looks like the
tier-wide check may have exactly one caller, with another tier doing something weaker
elsewhere.

**State what a check does *not* cover.** A guarantee described without its boundary is read as
wider than it is. Every invariant in this corpus carries its enforcement point and its
limits, and that second part is usually the useful one.

**A clean pass proves nothing until you have seen the check fail.** Before trusting a new
guard, make it fire deliberately. Several checks here passed for the wrong reason until
someone tried to break them.

**Verify against the code, not against a document — including this one.** Documents drift.
The line at the top of every file in this corpus is not decoration.

## Changing things

**Tests are the gate that runs.** The evaluation package is scaffolding with an empty
registry; behavioural guarantees belong in the ordinary suite. See
`architecture/eval-framework.md`.

**A signature change means auditing every caller**, including shell and end-to-end callers
that the unit suite does not exercise.

**Adding an option is never one edit.** The manifest, the schema, the translations, and
whatever reads it. Removing one additionally needs its key on the boot script's deprecated
list, or a stale stored value lingers. See `architecture/configuration.md`.

**Put a constraint where it will actually run.** A check inside a tool applies to every
caller. A check in an agent's declared tool list applies only to agents arriving through that
path, and a hook does not run when the hook service is unreachable — it fails open by design.
If the rule must always hold, the tool is the place. See `architecture/mcp-and-tools.md`.

**New durable state needs five decisions**, none of them inherited: where it is created, what
a missing file means, what a corrupt one means, whether the write is atomic, and whether it is
version-controlled. See `architecture/persistent-state.md`.

**Documentation is part of the change, not after it.** A document whose code moved is worse
than no document, because it is trusted. The corpus has a contract and a verifier; see
`contributing/doc-contract.md`.

## Publishing

This repository is public, and **the first push of anything is irreversible** — objects stay
fetchable after any deletion or force-push. The rule for what may be written here is one line,
and `doctrine/publishing.md` is the authority on it. Read it before adding prose that
describes anything beyond the code.

The short version: a fact belongs here only if it is verifiable from the public commit alone.
Not from a running system, not from an operator's knowledge, not from another repository.

## What to do when you are unsure

Say so. An explicit "I did not verify this" is worth more than a plausible sentence, because
the plausible sentence will be believed and the admission will be checked. Every serious
error in this corpus arrived as prose that sounded right.
